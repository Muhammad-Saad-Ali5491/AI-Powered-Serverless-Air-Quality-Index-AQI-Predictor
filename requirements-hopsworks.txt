# Optional: only needed if you set USE_HOPSWORKS=true.
#
# IMPORTANT: the `hopsworks` client pins pandas<2.2.0, which conflicts with
# pandas==2.2.2 in the main requirements.txt. Do NOT install this into the
# same environment as requirements.txt for local dev.
#
# Recommended usage:
#   - Locally: create a separate venv just for backfill/feature-pipeline
#     runs that write to Hopsworks, e.g.:
#       python -m venv venv-hopsworks
#       venv-hopsworks\Scripts\activate      (Windows)
#       source venv-hopsworks/bin/activate   (macOS/Linux)
#       pip install -r requirements.txt -r requirements-hopsworks.txt
#   - CI (GitHub Actions): the feature_pipeline.yml and training_pipeline.yml
#     workflows install this file automatically in a dedicated step only
#     when the USE_HOPSWORKS repo variable is set to "true", so day-to-day
#     CI runs never pay the install cost or hit the pandas conflict unless
#     you've opted in.
#
# Training/inference code itself (src/training, src/inference) still uses
# pandas==2.2.2 as normal — hopsworks is only imported inside
# HopsworksFeatureStore, and only for feature read/write calls, which the
# `hopsworks`/`hsfs` client handles internally regardless of the caller's
# pandas version in practice. If you hit a runtime pandas-version error
# from hsfs specifically, pin pandas==2.1.4 in this file's environment too.
